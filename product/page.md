# Product

PamAI is an AI-native project manager for founders and small-team operators.[^\[1\]^](https://app.pensieve.uk/r/506/data/17) It is positioned as “Your AI Project Manager, not another project management tool.”[^\[2\]^](https://app.pensieve.uk/r/506/data/14) Pam is a judgment-centered conversational intelligence—a strategist in conversation, not a chatbot or project board.[^\[3\]^](https://app.pensieve.uk/r/506/data/20) Its intended role is to take responsibility for the plan and leave the founder carrying the execution.[^\[4\]^](https://app.pensieve.uk/r/506/data/21) The product vision is an AI partner that understands the plan, watches the work, and takes the managing off the user's plate.[^\[5\]^](https://app.pensieve.uk/r/506/data/13)

## Product model

Pam starts from the question of what a project manager built from the ground up with AI should do, rather than adding AI to a pre-existing workflow.[^\[6\]^](https://app.pensieve.uk/r/506/data/17) Its development moved from a clunky task-management app with AI chat to a partner model that takes responsibility for the plan.[^\[7\]^](https://app.pensieve.uk/r/506/data/35)

The current responsibility model is: Foundation protects why, Planning protects what, Morning Brief protects today, Fulfillment protects what happened, Health protects truth over time, and Reflection protects conscious change.[^\[8\]^](https://app.pensieve.uk/r/506/data/188) The intended daily rhythm has Pam choose one top task and two supporting tasks, close the day by recording what moved, what did not, and what was learned, watch the project between sessions, and host a fortnightly reflection.[^\[9\]^](https://app.pensieve.uk/r/506/data/37) The division of labour is deliberate: “The user doesn't manage the project. Pam does. The user does the work.”[^\[10\]^](https://app.pensieve.uk/r/506/data/17) Pam is designed to give one answer for each need rather than ask the user to compare options.[^\[11\]^](https://app.pensieve.uk/r/506/data/65) The product-values framing has the user do three tasks a day and informally update Pam at the end of the day, while storing, documenting, planning, deciding, and reflecting sit with Pam.[^\[12\]^](https://app.pensieve.uk/r/506/data/65)

Foundation, Planning, and the operating rituals are now documented from current implementation and a fresh walkthrough on 2026-08-27; no future data model has been selected.[^\[13\]^](https://app.pensieve.uk/r/506/data/189) Whether “Full coverage of the workflow” returns as a named product value, and how collaboration or document generation fit that promise, remains undecided; the mechanics are now documented.[^\[14\]^](https://app.pensieve.uk/r/506/data/189) Pam's product doctrine is edited deliberately while idea capture accumulates separately; current implementation claims require Amir's direct account and the current codebase, and possible redesigns are kept separate from current implementation and assumptions.[^\[15\]^](https://app.pensieve.uk/r/506/data/184) See [Product Rituals](./product-rituals/page.md) for the retained setup-and-planning framing and the coarser four-stage journey into the daily rhythm.

## Product surface

Pam's user-facing work context combines workspaces and projects with conversations, files, and memory. The documented project surface includes projects, items, milestones, fronts, batches, and members; conversation records include chat messages, assistant replies, inbox messages, AI-generated summaries, and tool metadata; uploaded and project files plus user and project memory extend the context.[^\[16\]^](https://app.pensieve.uk/r/506/data/9)

The documented integration surface includes Telegram, WhatsApp, Google Calendar, Notion, ClickUp, and coding-agent client data, alongside user-requested integrations and imports.[^\[17\]^](https://app.pensieve.uk/r/506/data/9) Product-design documentation describes one-time migration tooling for existing project, document, and chat material from Jira, Notion, Google Docs, and prior Claude or ChatGPT use.[^\[18\]^](https://app.pensieve.uk/r/506/data/65) For these history imports, the intended mechanism is one-time migration rather than continuous syncing: Pam reads the old tool once, reports what it learned for confirmation, and then the user works inside Pam; development teams are an explicit Jira exception. This boundary does not describe ongoing operational connectors such as Google Calendar, Telegram or WhatsApp.[^\[19\]^](https://app.pensieve.uk/r/506/data/65)

The shipped surface is documented in detail by Negin's 27 August 2026 first-hour walkthrough of pamai.pm, recorded as a brand-new user; the full walkthrough and its designer feedback live on [Product Testing](./product-testing/page.md).[^\[20\]^](https://app.pensieve.uk/r/506/data/273) Signup runs through early-access verification and a guided, mostly-linear onboarding: a five-step "Monday Morning" narrative journey, free-text questions on current work and project stage, an optional success-in-four-weeks target, and a "Stay close to Pam" channel picker whose WhatsApp choice opened a real api.whatsapp.com deep link.[^\[21\]^](https://app.pensieve.uk/r/506/data/273) Onboarding answers then hand off verbatim into the app as a "HANDOFF FROM ONBOARDING" card — a literal compilation, not a paraphrase — which invokes the Project Foundation skill without asking the user to re-explain anything.[^\[22\]^](https://app.pensieve.uk/r/506/data/273) The handoff pattern repeats across both chat scopes, project-level "Pam setup" and workspace-level "Home setup".[^\[23\]^](https://app.pensieve.uk/r/506/data/273)

The app shell pairs a project chat thread whose model selector showed "Sonnet 5" with a right-hand project panel that gates itself to conversation progress — Project Fronts stay locked until the plan is built.[^\[24\]^](https://app.pensieve.uk/r/506/data/273) Plan-building runs as a dedicated six-step progress checklist, from reading context through building the initial plan, narrated as delegated to "one of my little Pams"; it produced two fronts and a milestone arc of Daily loop running, Pilot live, and Trust holding, shown on a current-milestone roadmap card.[^\[25\]^](https://app.pensieve.uk/r/506/data/273) Conversation silently builds two distinct artifacts: the project-facing "Project's Core" foundation notebook and a separate per-person "About Your Human" profile template with profile, working-preferences, goals, and constraints sections.[^\[26\]^](https://app.pensieve.uk/r/506/data/273) The product distinguishes background reference from working facts — in the walkthrough an uploaded pitch deck stayed as reference rather than having its extracted figures folded into the record.[^\[27\]^](https://app.pensieve.uk/r/506/data/273)

Calendar reality setup is live: Pam requests Google Calendar access and writes real time blocks from the week as described, including an added two-hour Sunday block.[^\[28\]^](https://app.pensieve.uk/r/506/data/273) Project settings expose Collaboration with Team Members email invites and a pending-invites list, Connectors with three connectable channels — Google Calendar, Telegram, and WhatsApp — and individually configurable Routines (Project health, Reflection session, and Dream mode were observed) whose schedule and model can be set per routine; the walkthrough's Project health routine was set to GLM 5.2 while main chat used Sonnet 5.[^\[29\]^](https://app.pensieve.uk/r/506/data/273) Account-level billing is credit-based: the walkthrough account sat on the Free plan with a wallet of 62.38 credits that never expire, alongside options to subscribe for a monthly pool of credits or buy top-ups.[^\[30\]^](https://app.pensieve.uk/r/506/data/273) A coding-agent connector screen offering a Claude Code connection was glimpsed,[^\[31\]^](https://app.pensieve.uk/r/506/data/273) the Notion connector pulled real prior project material into a second project, and Google Docs and ChatGPT history had no live connector — Pam asked for the key content pasted in instead.[^\[32\]^](https://app.pensieve.uk/r/506/data/273)

Two distinct sharing mechanisms sit side by side. Team Members under Settings > Collaboration is the ongoing-collaborator mechanism — full access, no time box, no credit budget, no file scoping.[^\[33\]^](https://app.pensieve.uk/r/506/data/273) A guest share is read-only and time-boxed, with per-file inclusion toggles, an explicit and explained credit budget for the guest's conversations (200 by default), a hard expiry, and mandatory email verification before access; the guest experience is a live, context-scoped Q&A that answers strictly from the approved context rather than a static document.[^\[34\]^](https://app.pensieve.uk/r/506/data/273)

Negin maintains a UI/UX Library for the web app interface — an ongoing reference library with an inspiration feed of good patterns spotted elsewhere and an issues feed of things currently off in Pam's own interface.[^\[35\]^](https://app.pensieve.uk/r/506/data/268) An entry starts when Negin shares a screenshot and is asked what specifically stood out; images are saved outside the repo under PAM Shared Media and indexed in inspiration.md and issues.md.[^\[36\]^](https://app.pensieve.uk/r/506/data/268) As of 2026-08-28 the library was newly set up and empty.[^\[37\]^](https://app.pensieve.uk/r/506/data/268)

## Stage and direction

In the June 2026 build-in-public account, PamAI was in MVP: a limited private group was testing it rather than participating in a public launch.[^\[38\]^](https://app.pensieve.uk/r/506/data/37) The test is about whether Pam actually removes management weight from a user's day, with attention to daily-brief quality, grounded plans, cognitive load, and operating cost rather than feature or UI coverage.[^\[39\]^](https://app.pensieve.uk/r/506/data/37) The repeatable cohort method lives on [Product Testing](./product-testing/page.md).

An unfinished business-model working draft gives a coarser four-stage journey before the daily rhythm begins:[^\[40\]^](https://app.pensieve.uk/r/506/data/63)

1. **Define** — a conversational Foundation session extracts the seven fields and builds a plan for the user and a mind for Pam.
2. **Confirm** — the user reads the plan, pushes back if it does not resonate, and Pam edits it.
3. **Reality setup** — Pam connects the calendar and allocates the project into the user's actual week.
4. **Daily rhythm** — the morning brief gives three tasks from the plan and calendar, chosen by Pam rather than the user.[^\[41\]^](https://app.pensieve.uk/r/506/data/63)

The draft treats Planning as likely folded into Define and Confirm at that level of detail.[^\[42\]^](https://app.pensieve.uk/r/506/data/63) The current implementation documentation treats Foundation and Planning as separate workflows, so the coarser journey should not replace the more precise operating model.[^\[43\]^](https://app.pensieve.uk/r/506/data/187)

The product brainstorm is explicitly “Not a roadmap, not commitments — just the idea bank.”[^\[44\]^](https://app.pensieve.uk/r/506/data/58) It records future directions such as role-aware plans, instant onboarding for new hires, capture-once call/interview intelligence, multi-channel access, always-on status and health, reflection conversations, and shareable or guest/viewer artifacts.[^\[45\]^](https://app.pensieve.uk/r/506/data/58) These ideas remain separate from the current product description and should not be treated as commitments.
